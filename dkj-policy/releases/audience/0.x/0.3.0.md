### DEPLOY: feat/200-repo-hub-pages · 20261017-220647Z

The Repo hub form has a new, optional block 7, **Pages** (#200): a data card titled "Pages", right under the
intro, with one link row per page of the repo's own (a label, an optional one-line description, a chevron).
It is built from the house `.menu-item` row, which gains `.menu-item__sub` and a hover on a link row, so a page
link never looks like a stat tile. The product button stays the intro's one button; the brand book's own
"Preview other repo hubs" moved from the intro into the block. React gets `PageLinks`; without React the
pattern page carries the markup. The blocks after it are renumbered 8 to 12.

**Score:** 3

#### What makes this deploy extra special

A repo's hub can now list the repo's own pages in the house form, with a `PageLinks` component (React) or the
`.menu-item` markup (without React); a repo with no page besides `/` and its product leaves the block out.

**Score:** 3

---

### DEPLOY: feat/199-repo-hub-name · 20261017-215754Z

The index of a repo's dev server is now called the Repo hub instead of the Repo dashboard (#199): the index
gets you to the page you want, and the pages below it can be dashboards. The house style fixes the new name
word for word as the `h1`, the one crumb on the index and the first crumb on every other page;
`house-style/README.md`, `patterns/repo-dashboard.html`, this repo's own index, its previews page ("Repo hub
previews") and the previews follow. File names, components, classes and URL paths are unchanged.

**Score:** 3

#### What makes this deploy extra special

The index page of a DKJ-Solutions dev server is now called **Repo hub**. An app that takes this house-style
version changes its index `h1`, its `<title>` and the first crumb of its breadcrumb bar from "Repo dashboard"
to "Repo hub"; nothing else changes.

**Score:** 3

---

### DEPLOY: feat/repo-default-themes · 20261017-212325Z

Every DKJ-Solutions repo has one default theme of its own, and all eight differ, so the apps are told apart
before anyone picks a theme. `house-theme.js` reads it from `<html data-theme-default="<id>">`, after the
user's own choice and before the light/dark pair, which keeps working for an app that has not moved yet; the
theme fixes the app's mode. `src/repos.ts` carries the eight (`DEFAULT_THEMES`, typed so a missing repo fails
`tsc`) and `house-style/README.md` lists them. The Repo dashboard shows each repo's default, and a repo's app
preview and dashboard preview open in it unless the viewer has picked a theme.

**Score:** 3

#### What makes this deploy extra special

Every DKJ-Solutions app gets a default theme of its own, and an app declares it with one attribute on its
`<html>`.

**Score:** 3

---

### DEPLOY: feat/width-full · 20261017-210257Z

The preview settings get a third width, `full`, next to `fluid` and `phone`: the content takes 100% of the page
column, so a repo preview that keeps its own app column in `fluid` now stretches edge to edge. The Repo dashboard
and the dashboard previews carry the Width toggle as well, which they did not before: there `fluid` is the house
column, `phone` a 360px column and `full` the whole width. `full` is the default until a reader picks another width.

**Score:** 2

#### What makes this deploy extra special

A reader of the brand book can now judge a component or a recreated app at the full width of their screen.

**Score:** 2
