# Release notes v0.4.0 🚀

**Date:** 2026-10-18\
**Type:** Minor\
**For whom:** consumers of this product, and colleagues in the organisation -- one section each

A page width setting -- fluid, phone or full -- in the house theme settings panel

## What changed

**Nothing breaks, and no action is needed.** No token, class, component or file is renamed or removed, so
taking the new copy of `house-style.css` and `house-theme.js` needs no migration.

### Let your users pick a page width

If your app draws the settings panel with `DKJTheme.settings(el)`, it now offers a page width next to the
theme: **fluid** (the house column), **phone** (360px) or **full** (the whole width). The choice is
remembered per device and applied before the page paints, and `main`, `.container` and the breadcrumb bar
follow it. No action needed: your app gets the group as soon as it takes the new copy.

### Choose your app's default width, or leave the group out

An app that is best read wide can start there with one attribute, `<html data-width-default="full">`; a
user's own choice still wins. An app where a width choice makes no sense passes `widths: false` to
`DKJTheme.settings(el)` and the group does not appear.

## What it is worth

The width toggle the brand book built for its own previews is now part of the house theme, so every
DKJ-Solutions app gets it from the stylesheet and the theme script rather than building its own. A
dashboard that needs the whole screen and a page checked at phone width are one setting each for the person
looking at them, with no developer involved. The brand book's own showcase and Repo hub moved to the shipped
setting, and a width a user had already stored carries over.
