# Release notes v0.2.0 🚀

**Date:** 2026-10-17\
**Type:** Minor\
**For whom:** consumers of this product, and colleagues in the organisation -- one section each

Dashboard previews for every repo, breadcrumbs on every page, and greyer primary greys

## What changed

**Nothing breaks.** No token is renamed or removed, so taking the new copy of `house-style.css` and
`house-theme.js` needs no migration. The one action is the breadcrumb bar below, and only for pages a dev
server serves.

### Add the breadcrumb bar to your dev server's pages

Every page a DKJ-Solutions dev server serves now opens with a breadcrumb bar that starts at **Repo
dashboard** and stays stuck to the top of the screen. It is a house rule. The stylesheet ships it as
`.breadcrumbs-bar` / `.breadcrumbs`, so you can use it without React too. The Repo dashboard pattern
shows it as block 0. **What you do:** add the bar to your pages. If you have a sticky element of your
own, move it from `top: 0` to `top: var(--tap)`, or the bar covers it.

### Greyer greys, same contrast

In every theme, `--primary-4`, `-5` and `-6` now read as grey with a hint of the theme instead of a muted
colour. That affects sub lines, notes, the pressed segment, the info badge and meter. Contrast is
unchanged. No action needed.

### The settings panel shows your theme's colour

With `DKJTheme.settings()`, the open toggle and the panel title are now `--primary-7`, the theme's own
colour, instead of grey. The theme picker's dots show each theme in its own colours. No action needed.

### Release notes written for you

From this release on, every minor and major release of the house style comes with a note like this one,
not only the per-PR list.

## What it is worth

Every DKJ-Solutions repo now has a dashboard preview in the brand book, so one page shows whether the
repos follow the house style. Checking that used to mean opening each repo on its own. The breadcrumb
bar gives every dev server the same way back to its Repo dashboard. Nobody has to explain an app's
navigation any more. The audience note makes each release readable for the repos that take it,
without reading thirteen PRs.

The release itself took **3m 13s** end to end, measured from the start of the cut (16:35:06) to the
last attachment landing (16:38:19). The cut, including its lint gate, ran 1m 53s up to the push.
The note, its gate and the Release with both attachments took the remaining 1m 20s. All of it blocked
the person cutting it.
